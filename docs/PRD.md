# LocalIM @ LAN — 产品需求（PRD）

## 1. 背景与目标

在**无外网/弱外网**的局域网环境，提供一款运行在已有 Chromium 内核技术栈上的
即时通讯与远程协作工具。产品**不依赖 arupa / nomad**，仅使用 `chromium/src` 系统组件，
避免任何中心服务器，数据在局域网内闭环。

## 2. 目标用户

- 内网办公 / 研发 / 运维团队，需要设备互通与远程协助。
- 三平台（Windows / macOS / Ubuntu）桌面环境。

## 3. 功能需求

### 3.1 设备发现
- **同网段自动发现**：启动即在多播组内广播存在性，秒级上线/下线感知。
- **跨网段发现**：经引导中继注册网段，在其它网段设备之间路由（网关注册 + 中继）。
- 设备卡片：名称、IP、网段、来源（lan/relay）、能力集。

### 3.2 单人聊天
- 文字、表情；图片/视频/语音（短）/任意文件收发。
- 实时远程连接（被控端注入输入，控制端看画面）。

### 3.3 群组聊天（自建）
- 建群/加群/退群/邀请/踢人；成员列表与同步。
- 文字/表情/图片/视频/语音/文件群发。
- 群共享桌面（房主 mesh 广播）。

### 3.4 媒体与传输
- 语音 / 视频通话；共享桌面。
- 文件分片传输 + 进度/确认，断点续传（roadmap）。

## 4. 非功能需求

- **三平台**：一套 UI + 平台原生输入注入；构建脚本按平台隔离差异。
- **本地优先**：无中心，relay 仅引导不存储。
- **局域网性能**：秒级发现；媒体走 P2P 直连，不依赖外网出带宽。
- **只读约束**：绝不引用 arupa/nomad 目录。

## 5. 架构形态

native 守护进程（`//base` `//net`）负责发现/信令/编排；WebUI（Vite+TS，被
Chromium 承载）负责界面与 WebRTC 媒体数据面。两者经 `ws://127.0.0.1:7615` 通信，
媒体经 `RTCPeerConnection` 于点间直连。详见 architecture.md。

## 6. 验收口径（骨架）

- 三平台能编译出 `localim_daemon` 并启动（端口就绪）。
- WebUI 构建通过并能连 7615。
- 同网段两台设备能互相发现并互发文字/图片。
- 跨网段经 relay 能发现；远程/共享/文件的数据面打通（见 roadmap 阶段划分）。

## 7. 范围外（本版不做）
- 云服务、账号体系、公网穿透；不追求与互联网 IM 的协议互通。
- 移动端；群 mesh 高可用（占位）。
- 消息 E2E 加密（WebRTC DTLS 已含传输层加密；信令 HMAC 留待打磨）。
